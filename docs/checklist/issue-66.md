自动验证：`cargo test -p tml-core -p tml-app`（`procctl`：优先级枚举与 Win32 常量映射、基本优先级对照、亲和性掩码与处理器列表互转、超过 64 个逻辑处理器的截断、空掩码 / 越界掩码校验、错误码；对自己启动的子进程真实改优先级与亲和性并回读、PID 复用识别为“已退出”、受保护的 System 进程（PID 4）与空闲进程被拒绝；`process_control`：菜单置灰与勾选判断、错误文案）；`pwsh scripts/test-process-priority.ps1`（`--menu-action` 钩子：逐档改优先级并用 .NET 回读、“实时”未确认不生效、亲和性缩到 CPU0 / CPU0+1 并回读、空掩码被拒绝、System 进程被拒绝且日志带错误码）；亲和性对话框离屏截图见 `docs/checklist/media/issue-66/affinity-dialog.png`。

以下只留下自动测试覆盖不到的观感与第三方程序行为（4 级，等回到电脑前）：

- [ ] 1. 右键菜单的子菜单与勾选观感（4 级）
  - 操作：进程页右键一个普通进程（如记事本），展开“设置优先级”；依次选“低于正常”“高”，每次再右键展开。
  - 预期：子菜单有六项（实时、高、高于正常、正常、低于正常、低），当前级别打勾，选后状态栏显示“已设置优先级”，再次展开时勾选跟着变；“优先级”列在下一次采样内更新。
  - 用户反馈：

- [ ] 2. “实时”需要确认，未提权时的说明（4 级）
  - 操作：对记事本选“设置优先级 → 实时”。
  - 预期：先弹确认框（提示可能让系统失去响应），点“取消”不改；点“设为实时”后，普通权限下状态栏提示系统把“实时”降为“高”，“优先级”列显示“高”；以管理员身份运行本程序时显示“实时”。
  - 用户反馈：

- [ ] 3. 亲和性对话框的操作与观感（4 级）
  - 操作：右键记事本 → “设置亲和性…”；点“全不选”（“确定”应置灰、提示至少选一个）、再点“全选”，只勾 CPU 0 和 CPU 1 后点“确定”；在资源监视器的 CPU 页或原生任务管理器“详细信息 → 设置相关性”里核对。
  - 预期：对话框列出全部逻辑处理器，勾选与当前亲和性一致；确定后对话框关闭、状态栏提示“已设置亲和性”，原生任务管理器里该进程只勾选了 CPU 0、1；记事本占用的核只在 0、1 上（资源监视器逐核观察）。
  - 用户反馈：

- [ ] 4. 受保护进程与拒绝访问的提示（4 级）
  - 操作：普通权限下右键 System（PID 4）、`csrss.exe`、`MsMpEng.exe` 等进程。
  - 预期：“设置优先级”各项与“设置亲和性…”置灰，不会崩溃；对没被预先置灰但最终被拒绝的进程，状态栏显示“没有权限修改该进程（受保护进程或需要管理员权限）…”。
  - 用户反馈：

- [ ] 5. 超过 64 个逻辑处理器的提示（4 级，需要这类机器，没有就跳过）
  - 操作：在逻辑处理器超过 64 的机器上打开“设置亲和性…”。
  - 预期：对话框列出当前处理器组的处理器，并明确提示“只支持当前处理器组”；确定后只改该组的掩码。
  - 用户反馈：

- [ ] 6. 进程在对话框打开期间退出（4 级）
  - 操作：对记事本打开“设置亲和性…”，不关对话框，先把记事本关掉，再点“确定”。
  - 预期：对话框保留，按钮上方显示“进程已经退出”，不崩溃。
  - 用户反馈：
