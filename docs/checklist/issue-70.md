自动验证：`cargo test -p tml-core -p tml-app`（core `winops`：窗口状态到菜单可用性的映射 `ops_enabled`、完整性级别比较 `needs_elevation`（普通权限 vs 提权 / System、本程序已提权、令牌被拒绝访问视为更高、其他原因读不到则允许尝试）、操作后回读状态判断成败 `succeeded`、错误码、失效句柄为 `Gone`、本进程令牌可读；app `window_ops`：菜单显示 / 置灰逻辑（应用行 vs 非应用行、正常 / 最大化 / 最小化、需要提权、句柄失效）与标题文案）；`cargo test -p tml-core --test apps -- --ignored notepad_is_app`（真实桌面：应用的窗口句柄与 `app_pids` 同键、属于记事本，对它最小化 / 还原 / 最大化后回读状态）；`pwsh scripts/test-window-ops.ps1`（`--menu-action window-*:<pid>[:group]` 钩子：最小化 / 还原 / 最大化 / 切换到的真实窗口状态、按状态置灰、对已处于目标状态的项强行触发被如实拒绝、平铺视图下菜单项隐藏且不执行、日志不含窗口标题）。

设计要点（验收时对照）：

- 窗口句柄在判定“应用”时顺带记下（`EnumWindows` 的 Z 序第一个应用窗口，即最上层的；UWP 记外层 `ApplicationFrameWindow`），不增加系统调用（枚举仍约 0.1 ms）；使用前校验 `IsWindow`，失效则状态栏写“窗口已关闭”。
- 提权应用：提权进程可以被打开，但普通权限读它的令牌会被拒绝访问（实测 Steam 提权时即如此），这种情况与“令牌完整性级别更高”一样处理，四项置灰并写“需要提权”。副作用：以另一个用户身份运行的同级窗口也可能被误判为需要提权。本程序以管理员运行时，提权应用不再置灰。
- “切换到”：最小化的窗口先 `SW_RESTORE`，再 `SetForegroundWindow`；用户刚点了本程序的菜单，本程序持有前台权限，正常能成功。不使用 `AttachThreadInput`、模拟按键等有副作用的绕过手段；被前台锁定拒绝时 `FlashWindowEx` 闪烁任务栏，状态栏提示“已闪烁任务栏，请手动切换”。
- 菜单：已最大化 → “最大化”灰；已最小化 → “最小化”灰；正常窗口 → “还原”灰（标题括号写原因）；“切换到”总是可用。最小化前最大化的窗口“还原”后回到最大化（系统行为）。
- 应用有多个窗口时只操作主窗口（最上层的那个）。已知限制：其他虚拟桌面上的窗口（#40）归入后台进程，不显示这些菜单项。
