自动验证：`cargo test -p tml-core -p tml-app`（`procctl`：版本阈值 build 16299、Control/State 掩码语义、PID 0 / 4 / 本程序拒绝、对自己启动的子进程真实开启 / 关闭并用 `NtQueryInformationProcess` 回读、开启时优先级降为低、关闭时恢复传入的优先级或保持用户的选择、已退出进程、采样器只在 `track_eco_mode` 开启时读取；`details`：“效率模式”列文字与按需判断；`process_control`：优先级恢复策略 `eco_restore_target`、菜单勾选 / 置灰 / 隐藏 `eco_menu`、应用行后代口径 `eco_targets`）；`pwsh scripts/test-ecoqos.ps1`（`--menu-action eco-mode:<pid>:<on|off>` 钩子：开启后回读 EcoQoS 与优先级为低、关闭后恢复开启前的优先级、开启期间手动改过优先级则关闭后不覆盖、应用行作用于后代、System 进程被拒绝且日志带错误码）。

设计要点（验收时对照）：

- 开启 = 进程电源节流（EXECUTION_SPEED）+ 优先级“低”；优先级子菜单的勾选随之变成“低”。
- 关闭时：优先级仍是“低” → 恢复到开启前记住的优先级（本程序重启后才看到的、别处开启的进程记不到，恢复为“正常”）；开启期间用户手动改过优先级 → 保持用户的选择，只关节流。
- 应用行（分组视图）作用于该应用及其全部后代（口径同“结束进程树”，explorer.exe 只作用自身），多于 1 个进程先弹确认框。
- Windows 10 1709（build 16299）以下菜单项与“效率模式”列都不出现。

以下只留下自动测试覆盖不到的观感与第三方程序行为（4 级，等回到电脑前）：

- [ ] 1. 原生任务管理器里的效率模式状态（4 级）
  - 操作：用本程序对记事本（或一个高占用进程）开启“效率模式”，同时打开原生任务管理器“详细信息”页。
  - 预期：原生任务管理器该进程的“效率模式”列/进程行显示叶子图标（已启用）；关闭后图标消失；反过来在原生任务管理器里开启后，本程序右键该进程“效率模式”打勾，开启“效率模式”列时显示“已启用”。
  - 用户反馈：

- [ ] 2. 高占用进程的 CPU 变化（4 级）
  - 操作：运行一个会吃满一个核的程序（如 `powershell -c "while($true){}"`），开启“效率模式”。
  - 预期：其 CPU 占用明显下降（被限制到节能运行），关闭后恢复；“优先级”列同步变为“低”再恢复。
  - 用户反馈：

- [ ] 3. 混合架构机器（大小核，如 12 代及以后的 Intel）迁到节能核（4 级，没有就跳过）
  - 操作：对高占用进程开启效率模式，在资源监视器 / 任务管理器 CPU 逐核视图里观察。
  - 预期：负载迁到能效核（E 核），关闭后回到性能核。
  - 用户反馈：

- [ ] 4. 右键菜单观感（4 级）
  - 操作：分别右键普通进程、System / csrss.exe 等关键进程、分组视图里的应用行。
  - 预期：普通进程的“效率模式”可点，已开启时打勾；关键进程置灰且标题写明“系统关键进程或本程序，不可开启”；没有权限的进程置灰且标题写明“没有权限”；应用行点击时若涉及多个进程先弹确认框，写明进程个数，取消不改。
  - 用户反馈：

- [ ] 5. 与“设置优先级”的联动观感（4 级）
  - 操作：对记事本先设“高于正常”，开启效率模式后展开“设置优先级”，再关闭效率模式后展开；再来一轮：开启后手动改成“高”，然后关闭效率模式。
  - 预期：开启后勾选在“低”；关闭后回到“高于正常”；第二轮关闭后仍是“高”，状态栏提示不含“优先级恢复”。
  - 用户反馈：

- [ ] 6. “效率模式”列（4 级）
  - 操作：列选择菜单里勾选“效率模式”，开启 / 关闭几个进程；再取消勾选。
  - 预期：列在下一次采样内更新（已启用 / 未启用）；点列头可排序；取消勾选后常驻开销回到原来的水平（可用 `scripts/measure-idle.ps1` 对比）。
  - 用户反馈：
