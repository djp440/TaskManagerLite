# Issue #72 服务页修改启动类型验收

自动验证：启动类型与 Win32 值 / 命令行写法互转（含延迟自动）、驱动与受保护服务的置灰判断、只有“未提权 + 拒绝访问”才走 UAC 子进程及其参数可被子进程解析回原动作、错误与提示文案、日志字段（`cargo test -p tml-core -p tml-app`）。`pwsh scripts/test-service-start-type.ps1`：普通权限下 RpcSs 菜单打勾“自动”且可用、受保护服务（本机为 AppIDSvc）菜单置灰并注明原因、普通权限修改被拒绝（错误码 5）且进程不崩溃、`sc qc` 读回未变；提权终端下另建临时服务 `tml-test-svc`，依次改为已禁用、自动（延迟启动）、自动、手动并用 `sc qc` 核对，最后删除。

- [ ] 1. 菜单观感与打勾（4 级）
  - 操作：普通权限启动本程序，进入“服务”页，右键任一服务行，展开“启动类型”子菜单；再右键一个受保护服务（如 AppIDSvc、WinDefend）。
  - 预期：子菜单有“自动”“自动（延迟启动）”“手动”“已禁用”四项，当前值打勾，未提权时每项前有盾牌图标（深浅色主题下都看得清）；受保护服务四项置灰，子菜单标题显示“启动类型（受系统保护的服务，不能修改启动类型）”。以管理员身份运行时不显示盾牌。
- [ ] 2. UAC 提权与取消（4 级）
  - 操作：普通权限下先在管理员终端执行 `sc create tml-test-svc binPath= "C:\Windows\System32\cmd.exe /c exit" start= demand`；在服务页右键 `tml-test-svc` →“启动类型”→“已禁用”，UAC 弹出时点“否”；再重复一次并点“是”；然后改回“手动”。最后 `sc delete tml-test-svc`。
  - 预期：底栏先显示“正在将服务“…”的启动类型改为“已禁用”（需要管理员权限，请在 UAC 对话框中确认）…”；取消时显示“无法将服务…的启动类型改为“已禁用”：操作已被用户取消”，列表中启动类型不变；确认后显示“已将服务…改为“已禁用””，“启动类型”列立即变为“已禁用”，`sc qc tml-test-svc` 为 `DISABLED`；改回后为 `DEMAND_START`。
- [ ] 3. 延迟自动启动与 services.msc 一致（4 级）
  - 操作：对 `tml-test-svc`（或另一可安全测试的服务）分别设为“自动（延迟启动）”和“自动”，每次后在 `services.msc` 中刷新查看该服务的“启动类型”；再从“自动（延迟启动）”直接改为“手动”。
  - 预期：`services.msc` 依次显示“自动(延迟启动)”“自动”“手动”，与本程序“启动类型”列一致；从延迟自动改为手动后再改回“自动”时不会残留“延迟启动”。
