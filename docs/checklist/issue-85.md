# Issue #85 进程与服务互相跳转：验收

自动验证：`cargo test -p tml-core -p tml-app`（core `services`：`host_map` 按 PID 分组并排序、未运行服务不计入、`apply_hosts` 清回 None、真实枚举含 RpcSs 且约 1 ms；`sampler`：服务列默认不枚举、开启后进程带服务、缓存期内不重复枚举、关闭清缓存；`details`：服务列排序；app `details`：服务列文字（空 / 单个 / 多个 / 超过 6 个截断）、`needs_services`；`services_page`：按 PID 过滤与搜索叠加；`process_menu`：“转到服务”可用性；`export`：服务列进 CSV 且与界面文字一致）；`pwsh scripts/test-goto-service.ps1`（`--menu-action goto-service:<pid>`：对 svchost 跳转后服务页行集合与 `Win32_Service` 一致、过滤状态与选中第一行、提示条文字、对不承载服务的 ping 菜单项置灰且不跳转、CSV 里的“服务”单元格与 Win32_Service 一致；截图保存在 `docs/checklist/media/issue-85/`）。

设计要点（验收时对照）：

- “服务”列默认不显示，显示后才由采样器每 5 秒枚举一次服务（只枚举名称与 PID，不读启动类型等配置），隐藏即停止；右键菜单弹出时现枚举一次（约 1 ms）判断“转到服务”是否可用。
- “转到服务”切到服务页后只显示该 PID 承载的服务，顶部有提示条；第一次进入服务页枚举是异步的，等枚举完成后才选中第一项。
- 过滤在以下时机清除：在服务页搜索框输入（含 Esc 清空）、点提示条“清除过滤”、切到其他页面。

  - 预期：svchost 的菜单项可点，点后切到服务页，只显示它承载的服务，第一行高亮；不承载服务的进程该项置灰。
