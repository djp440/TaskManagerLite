# 0004 用私有内核 ETW 会话统计进程磁盘速率

状态：已接受（2026-10-28），修订 ADR-0001 的“已知近似”一节。**默认关闭**，提权人工验收通过后再翻默认值。

## 背景

ADR-0001 里进程“磁盘速率”取自 `ReadTransferCount + WriteTransferCount` 的差值，包含管道、网络等非磁盘 I/O，比原生任务管理器偏高。issue #5 要求评估并实现基于 ETW 磁盘事件的准确值。实现时开发环境没有管理员权限，无法实测开销与准确度，所以先以“可选、默认关闭”的形态合并。

## 决定

设置项 `accurate_disk_io`（`settings.json`，默认 `false`）为 `true` 且程序已提权时，在首个快照之后启动一个私有的内核 ETW 会话，按进程累计磁盘字节数，覆盖近似速率；列头不再显示“≈”。设置页（#16）以后接这个开关。

- **关闭时完全不碰 ETW**：不检查提权以外的任何系统状态、不清理残留会话、不安装 panic 钩子或异常过滤器、不创建线程，零开销。这些都只发生在 `DiskTrace::start` 里。
- **运行中切换**：`Sampler::set_accurate_disk(bool)`（采样线程命令 `AccurateDisk`）。关闭→开启：下一次非首次采样启动会话；开启→关闭：立即停止会话并恢复近似速率。
- **会话类型**：`EVENT_TRACE_SYSTEM_LOGGER_MODE`（Windows 8+）的私有会话，`EVENT_TRACE_REAL_TIME_MODE`，QPC 时钟。不使用全局唯一的 “NT Kernel Logger”，因此不会和 Process Monitor、WPR、xperf 等工具抢占它。
- **会话名**：`TaskManagerLite-DiskIo-<PID>-<进程创建时间十六进制>-<序号>`。序号在同一进程内递增（运行中反复开关时，旧会话的收尾线程不会误停新会话）。
- **事件来源**：`EnableFlags = DISK_IO | THREAD`。
  - `DiskIo` 的 Read/Write（操作码 10/11）给出传输字节数。事件在 DPC 中完成时记录，事件头里的进程号不可靠，要用版本 3 负载里的 `IssuingThreadId`，经线程表还原到进程。
  - `Thread` 的 Start/DCStart/End 维护线程到进程的表（会话启动时内核会枚举已有线程）。线程表里没有的线程，向系统查询（`OpenThread` + `GetProcessIdOfThread`），查不到的线程号在本窗口内缓存为“缺失”，不重复查询；仍不行才退回事件头进程号。已结束线程的记录推迟到下一次取数才删除，避免晚到的磁盘事件无法归属。
  - 不开启上下文切换、文件 I/O、进程、网络等事件。
- **缓冲区**：单块 16 KB，最少 2×处理器数、最多 4×处理器数块（非分页内存，约 0.4–0.8 MB，12 核）；`FlushTimer = 1` 秒，实时模式下缓冲区最迟 1 秒送达。磁盘事件每秒几百条、每条约 100 字节，足够。
- **消费**：后台线程里 `StartTrace → OpenTrace → ProcessTrace`，回调只做 GUID 比较、解析和一次加锁累加（只有遇到未知线程才在锁外查询系统后再加一次锁）；采样线程每次采样取走并清零累计值，除以采样间隔得到速率。会话在首次采样之后才启动，不影响冷启动。会话刚就绪的那一次采样丢弃（窗口只有半截）。
- **有界内存**：窗口最小化或暂停时采样线程不取数，但事件仍在到达。聚合器的所有表都有上限：线程表 131072 项、已结束标记 16384 项（超过就提前回收）、按进程累计表与“缺失”缓存各 65536 项。选择在回调里限界、保持会话常驻，而不是暂停时停止会话，是为了避免反复启停带来的开销和恢复后的半截窗口。限界的代价只是极端情况下少记或需要重新向系统查询，不影响正确性。
- **“准确”的运行时校验**：每个窗口统计磁盘事件数与“无法还原发起线程、退回事件头进程号”的事件数；窗口内事件不少于 20 条且无法归属的超过 20% 时，该窗口回报 `Approximate`，列头恢复“≈”，保留近似速率。这样即使线程枚举事件或负载版本与预期不符，也不会把错误归属冒充“准确”。
- **开销预算**：提权并开启后 `measure-idle.ps1` 的 CPU 增量应在测量噪声内（目标不超过 +0.1 个百分点）；超出则保持默认关闭。数据见 PR 的人工验收项（开发环境未提权，无法实测）。

## 权限与回退

内核会话需要管理员权限。未开启或未提权时不做任何尝试，继续使用近似速率，列头显示“磁盘 ≈”。启动失败（拒绝访问、会话数已满等）或会话被外部停止时，同样自动回退，且不自动重试（重新开关设置才会再试）。我们不提权、不修改系统配置、不写 HKLM。

## 会话生命周期

ETW 会话属于系统而不是进程，进程消失后不会自动停止，所以分层兜底：

1. 正常退出：`main` 开头持有 `TraceGuard`，任何返回路径（含 `?`）都会停止会话。`DiskTrace` 被丢弃时只停止自己 `StartTrace` 成功的会话；启动线程尚未走到那一步时，由它看到取消标记后自行停止。
2. panic：panic 钩子（release 为 `panic = abort`，钩子在 abort 之前运行）停止会话。
3. 未处理异常（访问违规等）：`SetUnhandledExceptionFilter` 里尽力停止会话。**钩子与过滤器里不做堆分配、不加锁**：会话启动成功后预先构造并泄漏停止用的 `EVENT_TRACE_PROPERTIES` 缓冲与 UTF-16 会话名（几 KB），崩溃路径上只做原子标记和一次 `ControlTraceW`。
4. 进程被强行结束（`TerminateProcess` 等）无法在进程内清理：下一次**启动会话时**（开关开启且提权），后台线程用 `QueryAllTracesW`（返回 `ERROR_MORE_DATA` 时扩大到 256 个再查一次）枚举会话，名称带本程序前缀且属主已不存在的一律停止。属主“已不存在”的判定保守：只有 `OpenProcess` 报 `ERROR_INVALID_PARAMETER`（PID 不存在）、创建时间对不上（PID 被复用）或确认已退出才算；拒绝访问等其他错误一律视为存活，宁可漏清也不误停。此前残留的会话只会丢事件，开销很小，直到下次开启时被回收（或重启系统）。

多实例（`--allow-multiple`）各自使用带自己 PID 的会话名，互不干扰；清理只针对属主已不存在的会话。

## 取舍

- 打开 `Win32_System_Diagnostics_Etw`、`Debug`、`Kernel`、`Time` 四个 `windows` 特性，release exe 约增加 0.1 MB。
- 缓存写入由系统线程（惰性写入器）发出，会归属于 System 进程，而不是写文件的进程；这与资源监视器的口径一致，也是“准确”的含义：按实际发起磁盘 I/O 的进程统计。
- 没有换用 `Microsoft-Windows-Kernel-Disk` 等清单式提供者：它们同样要提权，而经典内核事件加线程表的归属逻辑成熟、字段稳定。

## 验证

- 事件解析、按进程聚合、速率换算、容量上限、归属质量判定是纯函数，用构造的事件序列单测（`diskio.rs`）；会话名往返、残留属主判定、停止上下文预构造单测（`etw.rs`）；开关默认关闭与运行中切换单测（`sampler.rs`）；设置项往返与错误类型回退单测（`settings.rs`）。
- 未提权时强行启动会话，应以 `ERROR_ACCESS_DENIED` 失败而不挂起、不崩溃（`etw.rs` 单测）。
- 提权下的端到端验收：`scripts/test-etw-disk.ps1`（生成临时文件写入，核对该进程的 ETW 字节数、会话在进程退出后消失、残留会话被下次启动清理，并输出近似速率对比）。与资源监视器的对比和 CPU 增量是人工验收项。验收通过后再讨论把默认值翻为开启。
