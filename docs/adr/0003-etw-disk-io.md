# 0003 用私有内核 ETW 会话统计进程磁盘速率

状态：已接受（2026-10-28），修订 ADR-0001 的“已知近似”一节

## 背景

ADR-0001 里进程“磁盘速率”取自 `ReadTransferCount + WriteTransferCount` 的差值，包含管道、网络等非磁盘 I/O，比原生任务管理器偏高。issue #5 要求评估并实现基于 ETW 磁盘事件的准确值。

## 决定

提权运行时，在首个快照之后启动一个私有的内核 ETW 会话，按进程累计磁盘字节数，覆盖近似速率；列头不再显示“≈”。

- **会话类型**：`EVENT_TRACE_SYSTEM_LOGGER_MODE`（Windows 8+）的私有会话，`EVENT_TRACE_REAL_TIME_MODE`，QPC 时钟。不使用全局唯一的 “NT Kernel Logger”，因此不会和 Process Monitor、WPR、xperf 等工具抢占它。
- **会话名**：`TaskManagerLite-DiskIo-<PID>-<进程创建时间十六进制>`，由本程序标识 + 属主进程身份唯一确定。
- **事件来源**：`EnableFlags = DISK_IO | THREAD`。
  - `DiskIo` 的 Read/Write（操作码 10/11）给出传输字节数。事件在 DPC 中完成时记录，事件头里的进程号不可靠，要用版本 3 负载里的 `IssuingThreadId`，经线程表还原到进程。
  - `Thread` 的 Start/DCStart/End 维护线程到进程的表（会话启动时内核会枚举已有线程）。线程表里没有的线程，向系统查询（`OpenThread` + `GetProcessIdOfThread`）；仍不行才退回事件头进程号。已结束线程的记录推迟到下一次取数才删除，避免晚到的磁盘事件无法归属。
  - 不开启上下文切换、文件 I/O、进程、网络等事件。
- **缓冲区**：单块 16 KB，最少 2×处理器数、最多 4×处理器数块（非分页内存，约 0.4–0.8 MB，12 核）；`FlushTimer = 1` 秒，实时模式下缓冲区最迟 1 秒送达。磁盘事件每秒几百条、每条约 100 字节，足够。
- **消费**：后台线程里 `StartTrace → OpenTrace → ProcessTrace`，回调只做 GUID 比较、解析和一次加锁累加；采样线程每次采样取走并清零累计值，除以采样间隔得到速率。会话在首次采样之后才启动，不影响冷启动。会话刚就绪的那一次采样丢弃（窗口只有半截）。
- **开销预算**：提权后 `measure-idle.ps1` 的 CPU 增量应在测量噪声内（目标不超过 +0.1 个百分点）；超出则回退为不默认开启。数据见 PR 的人工验收项（开发环境未提权，无法实测）。

## 权限与回退

内核会话需要管理员权限。未提权时不做任何尝试，也不引入额外开销，继续使用近似速率，列头显示“磁盘 ≈”。启动失败（拒绝访问、会话数已满等）或会话被外部停止时，同样自动回退。我们不提权、不修改系统配置。

## 会话生命周期

ETW 会话属于系统而不是进程，进程消失后不会自动停止，所以分层兜底：

1. 正常退出：`main` 开头持有 `TraceGuard`，任何返回路径（含 `?`）都会停止会话。
2. panic：panic 钩子（release 为 `panic = abort`，钩子在 abort 之前运行）停止会话。
3. 未处理异常（访问违规等）：`SetUnhandledExceptionFilter` 里尽力停止会话。
4. 进程被强行结束（`TerminateProcess`、断电前的任务管理器结束等）无法在进程内清理：下一次启动时，后台线程用 `QueryAllTracesW` 枚举会话，名称带本程序前缀且 PID + 创建时间对不上任何存活进程的，一律停止。此前残留的会话只会丢事件，开销很小，直到下次启动被回收（或重启系统）。

多实例（`--allow-multiple`）各自使用带自己 PID 的会话名，互不干扰；清理只针对属主已不存在的会话。

## 取舍

- 打开 `Win32_System_Diagnostics_Etw`、`Debug`、`Kernel`、`Time` 四个 `windows` 特性，release exe 约增加 0.1 MB。
- 缓存写入由系统线程（惰性写入器）发出，会归属于 System 进程，而不是写文件的进程；这与资源监视器的口径一致，也是“准确”的含义：按实际发起磁盘 I/O 的进程统计。
- 没有换用 `Microsoft-Windows-Kernel-Disk` 等清单式提供者：它们同样要提权，而经典内核事件加线程表的归属逻辑成熟、字段稳定。
- 窗口最小化期间采样暂停，会话仍在运行，只累计很小的 map；是否在暂停时停止会话留待实测后决定。

## 验证

- 事件解析、按进程聚合、速率换算是纯函数，用构造的事件序列单测（`diskio.rs`）；会话名往返与残留识别单测（`etw.rs`）。
- 未提权时强行启动会话，应以 `ERROR_ACCESS_DENIED` 失败而不挂起、不崩溃（`etw.rs` 单测）。
- 提权下的端到端验收：`scripts/test-etw-disk.ps1`（生成临时文件写入，核对该进程的 ETW 字节数、会话在进程退出后消失、残留会话被下次启动清理，并输出近似速率对比）。与资源监视器的对比和 CPU 增量是人工验收项。
